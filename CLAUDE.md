## Architecture

This is a **flake-parts + import-tree** NixOS configuration. `flake.nix` has no central `configuration.nix` — it imports the entire `./modules` directory via `import-tree`, and every `.nix` file there contributes to the flake via `flake.modules.*` attrsets.

### Module structure

- `modules/hosts/desktop-nixos/` and `modules/hosts/laptop-nixos/` — host definitions. Each `default.nix` contains a `modules` string list selecting which features to enable for that host, plus a `hardware-configuration.nix` generated by `nixos-generate-config`.
- `modules/features/` — reusable feature modules, organized by category (`programming/`, `desktop/`, `apps/`, `browsers/`, `custom-scripts/`).
- `modules/{meta,parts,systems}.nix` — flake-parts scaffolding (per-system nixpkgs, system list, metadata like default terminal/browser).
- `modules/hosts/configurations.nix` — `mkSystems` / `loadNixosAndHmModuleForUser` helpers that assemble hosts from the feature list.

### Dual-module pattern

Most feature modules define both a NixOS part and a home-manager part under the same name:

```nix
# modules/features/programming/git.nix
{inputs, ...}: {
  flake.modules = {
    nixos.git  = {pkgs, ...}: { environment.systemPackages = [...]; };
    homeManager.git = {config, ...}: { programs.git = {...}; };
  };
}
```

When a host enables `"git"` in its modules list, `loadNixosAndHmModuleForUser` imports both `flake.modules.nixos.git` (system) and `flake.modules.homeManager.git` (user `wiktor`).
